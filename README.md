# RustdeskIsland

**开箱即用**的 RustDesk 远程控制被控端插件。**不安装完整程序**：插件包内置 RustDesk 程序文件，首次启用时绿色部署到插件配置目录，并仅以 `sc create` 注册**后台服务**（服务指向插件目录中的程序）。服务启动后自动以**托盘方式最小化运行**（无窗口驻留系统通知区）。远控方在任意 RustDesk 客户端**输入本机 ID** 即可连接。

**仅包含被控端功能**（不提供主控界面，不写开始菜单/注册表安装信息、不装 Program Files）。

## 工作方式（与官方安装版的区别）

| | 官方 MSI 安装 | 本插件 |
| --- | --- | --- |
| 程序位置 | `C:\Program Files\RustDesk` | 插件配置目录 `bin\`（绿色部署） |
| 安装行为 | 完整安装（快捷方式/注册表/服务） | 仅注册后台服务（winsvc API，binpath 指向插件目录） |
| 服务 | `RustDesk` | 同名 `RustDesk`（与官方 CLI/IPC 完全兼容） |
| 托盘 | 开始菜单启动项 | 插件自动以 `--tray` 拉起（无窗口最小化） |
| 卸载 | 卸载程序 | 插件内“卸载服务”即可 |

服务状态同步直接 P/Invoke SCM（`OpenSCManager` / `OpenService` / `QueryServiceStatus`），
不解析任何命令行文本输出，因此在中文等非英文系统上同样可靠。

### 提权助手（helper）

服务注册、启停与配置写入需要管理员权限，由插件内附带的
`helper/RustdeskIsland.Helper.exe` 完成：

- **为什么需要它**：ClassIsland 以普通权限运行，服务管理必须经 UAC 提权。
  助手里只做三件事——建/删服务、启停服务、调 RustDesk 官方 CLI 写配置，
  全部使用 `advapi32.dll` 的服务控制 API，不拼 `sc.exe` 命令、不生成 PowerShell 脚本。
- **技术选型**：用 Windows 自带的 `csc.exe` 编译成 .NET Framework 4.x 程序，
  由系统内置 CLR 直接运行（约 18 KB）。不依赖 .NET 8 运行时，也不使用单文件打包——
  后者在本机的自解压启动环节会静默失败。
- **参数传递**：宿主把操作写成 UTF-8 请求文件（`action=`、`binary=`、`option.<键>=<值>`、
  `password=`），命令行只传文件路径。因此**中文密码、中文安装路径都不受编码影响**，
  密码也不会出现在进程命令行里；助手用完即删请求文件。
- **返回值**：助手写出结果文件（首行 `ok=0/1`，其余为日志），宿主读取并显示。
  RustDesk 的 CLI 出错时仍以退出码 0 返回，因此助手按**输出文本**判定成败。
- **服务启动类型**：创建服务时一律先用 `SERVICE_AUTO_START` 建出来，再用
  `ChangeServiceConfig` 单独设置启动类型——「开机自启」用 `AUTO_START`（并开启延迟启动，
  不拖慢开机），「手动启动」用 `DEMAND_START`。
  **这里绝不使用 `SERVICE_DISABLED`**：被禁用的服务任何启动请求都会被 SCM 直接拒绝
  （`StartService` 返回 `1058 ERROR_SERVICE_DISABLED`），界面上也点不亮。
  因此「服务无法启动」表现为已安装却永远启动不了。
- **可自愈**：若检测到服务处于禁用状态（老版本留下的坏状态），助手会先改回
  `DEMAND_START` 再启动，无需用户手动清理。
- **安装即启动**：点击「安装服务」后助手会立即尝试启动服务，装完即可用，
  不会停在「已安装但未运行」的中间态。
- **重复安装容错**：若同名服务还处于「已标记删除」（`1072`）的过渡状态，
  助手会等待它从 SCM 消失后再新建，而不是直接报错失败。

### 关于 `C:\Program Files\RustDesk`

RustDesk 的 `--option` / `--password` / `--set-id` 有一条 `is_installed()` 门禁：
它检查官方安装目录 `C:\Program Files\RustDesk\RustDesk.exe` 是否存在，
不通过时只打印 `Installation and administrative privileges required!`
并以退出码 0 返回（看起来像"没反应"）。

由于实际运行的程序在插件目录里，助手会放置一个 **0 字节占位文件**满足该门禁——
**不是完整安装**，插件程序目录里不会出现 78 MB 的 RustDesk。
若你本机已有官方 RustDesk 安装，则保持原样不动；
卸载服务时也只清理自己创建的空占位文件（有真实安装则不动）。

## 使用方法（无需安装 RustDesk）

1. 打开【应用设置】→【RustdeskIsland】。
2. 打开**启用被控端**开关。插件自动：绿色部署内置程序 → 注册并启动后台服务（首次一次 UAC）→ 以托盘方式最小化运行。
3. （推荐）设置**固定访问密码**与**接受连接方式 = 自动接受**，点击**应用设置**，即可实现无人值守访问。
4. 把状态区显示的**本机 ID** 告诉远控方，对方在任意 RustDesk 客户端中输入该 ID 即可连接。

## 可配置项（全部在插件设置页面）

- **被控端**：启用开关、服务开机自启、**托盘最小化运行**、安装/卸载/启动/停止服务按钮
- **服务器**：官方服务器 / 自定义服务器（ID 服务器、公钥、中继、API）
- **连接与密码**：固定访问密码、接受连接方式（保持默认/自动接受/手动确认）、访问权限模式（完全访问/仅屏幕共享/自定义）
- **权限**：键盘鼠标、剪贴板、文件传输、声音、摄像头、终端、TCP 隧道、远程重启、拦截本机输入、远程打印、会话录制
- **高级**：指定外部 RustDesk 路径（留空 = 使用内置部署）

## 多平台自动适配

| 平台 | RustDesk 来源 | 服务管理 | 托盘 | 配置写入 |
| --- | --- | --- | --- | --- |
| Windows | **内置（默认）**，绿色部署 | winsvc API（经提权助手） | `--tray` 自动拉起 | 官方 CLI（经提权助手） |
| Linux | 内置/系统安装均可 | systemd 单元 `rustdesk` | — | 直接执行（需 root/sudo） |
| macOS | 内置/系统安装均可 | launchd | — | 直接执行（需 sudo） |

配置通过 RustDesk 官方 CLI（`--option`、`--password`）经 IPC 写入后台服务——服务进程读取的配置文件与当前用户不同，直接改写用户目录下的配置文件不会生效（RustDesk 源码 `config.rs` 的 `patch()` 会重定向服务配置目录）。

## 内容物

- 内置 RustDesk **1.5.0** 程序文件（Windows x64，官方发行版，93 个文件；含服务端与托盘运行所需全部组件，不含打印机/虚拟显示驱动包）
- 提权助手 `helper/RustdeskIsland.Helper.exe`（约 21 KB，.NET Framework 4.x，系统内置 CLR 运行）
- 插件后台服务：绿色部署、服务注册/启停、状态同步、ID 读取、托盘管理
- 完整设置界面（服务器/密码/权限/服务管理）

## 兼容性

- ClassIsland **2.0.0.0+**（`apiVersion: 2.0.0.0`）
- 插件 SDK：`ClassIsland.PluginSdk 1.7.106.2-dev-v2`
- Windows 10 1803+ / x64（Linux、macOS 走内置或已安装的 RustDesk）
